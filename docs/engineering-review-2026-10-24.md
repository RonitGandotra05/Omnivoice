# OmniVoice engineering review — 24 October 2026

## Product and architecture

The deployed application is a Next.js 15 / React 19 studio. Google OAuth uses NextAuth encrypted sessions; application session and MFA helpers recheck PostgreSQL account state. PostgreSQL holds verified accounts, identity mappings, MFA state, authentication guards/events and shared voice/operation quotas. In the configured browser storage mode, company profiles, documents, caller records, transcripts and callback requests live in IndexedDB. Parsing uses local PDF/DOCX/OCR workers. Approved text is published to private ElevenLabs agents; browser calls use owner-bound grants and signed WebSocket URLs. An optional encrypted PostgreSQL workspace adapter supports connected company operations. Retained Python/FastAPI, telephone and SMTP paths are separate integrations, not prerequisites for the current studio.

Source review covered the application routes, account/OAuth/MFA and operator authorization, studio handlers, database adapters and schema setup, document processing, publishing/preparation, provider communication, voice component and SDK implementation, navigation, account settings, deployment settings and retained backend access controls. Existing functionality was preserved where it already had appropriate controls.

## Implemented outcomes

- Replaced the unusable legacy dashboard with current product administration. The configured database has `ov_*` tables and no `users`, `agents`, `bookings` or legacy conversation tables. Metrics now query actual current tables instead of failing against the legacy schema.
- Applied an additive, transactional migration to the configured frontend database. The existing verified `ronitgandotra@gmail.com` account is the only administrator. No duplicate owner account was created. A database check constraint limits the role to that active verified email; a partial unique index limits administrator count to one. The assignment script verifies its result and invalidates old sessions when a role changes. It is repeatable and available as `npm run setup:admin`.
- Added server-protected `/admin/dashboard`, `/api/admin/overview` and `/api/admin/accounts`. Authorization checks the signed session and current account/MFA state; every privileged API independently checks the database-backed role and canonical verified identity. Altering local storage or client-rendered state does not grant access.
- Added real account totals, retained voice reservation/settlement counts, UTC daily activity, authentication events, integration configuration and protection-counter views. Reserved minutes are explicitly distinct from settled usage. Counters are not labeled billable API calls; costs are not fabricated. Browser-local documents/transcripts are explicitly outside the dashboard's scope.
- Added paginated account management, suspension/restoration, session revocation, protected administrator identity, action confirmation, duplicate-submit guards, request deadlines, retry feedback and transactionally persisted administrator action logs. These controls cannot assign roles. Suspension/revocation does not terminate an already-issued external provider connection; provider duration caps remain its boundary.
- Added conditional Admin navigation for the real administrator, including the compact menu. Mobile navigation supports Escape and restores focus. Safe local callback destinations return users to the requested page after Google/MFA sign-in. Account/studio session failures offer retry controls, and account refresh/sign-out propagate across tabs without sharing tokens.
- Prevented early edits/saves before the saved studio workspace finishes loading, with a cancellable initialization request and explicit retry state on startup failure. This avoids accidentally overwriting saved content with the initial sample data.
- Fixed voice startup readiness for the installed SDK, which returns void from `startSession`. The UI now waits for connection callbacks, rejects early disconnects/errors, and uses a connection deadline. Startup describes microphone permission, knowledge preparation, session issuance and connecting separately. Late microphone permission grants release their tracks even after cancellation or timeout.
- Fixed a permanent voice retry lockout: this SDK exposes an `error` status, and the old UI allowed starts only from `disconnected`. Both idle states now allow a new attempt; live/pending states remain guarded. End controls avoid repeated termination and represent disconnecting state. Microphone permission, missing-device, busy-device and network failures receive actionable messages.
- Coalesced voice allowance refreshes and scheduled polling after completion, preventing overlapping provider reconciliation requests. Quota lookup failure no longer takes down authenticated account/settings/admin navigation; voice issuance retains its independent fail-closed protection.
- Converted workspace reads and GET operations to read-only IndexedDB transactions. Reading/polling no longer rewrites the full document library or increments its revision. Mutations retain serialized atomic transactions.
- Restricted the retained operator adapter to the same canonical administrator email. The optional connected studio accepts the new verified product administrator alongside its existing authenticated integration mechanism.
- Extended secret scanning to include unstaged and untracked non-ignored source, alongside staged Git blobs and browser bundles. A regression check confirms untracked credentials are rejected without printing their values.
- Updated Nodemailer to a patched release. Full npm audit reports zero known vulnerabilities, including development dependencies.
- The retained Python environment initially reported 64 advisories across eight installed packages. Updated pinned Pillow/pypdf and certificate dependencies, updated vulnerable local packaging/tooling dependencies, removed unused python-jose/ecdsa remnants (the code uses PyJWT), and updated the container packaging-tool bootstrap. The final installed-environment pip audit reports zero known vulnerabilities and pip dependency consistency passes.

## Production assessment and remaining gates

This is a substantial implemented hardening pass, not a certification of every interface or integration. Code changes have not been pushed or deployed; the administrator assignment was applied to the database configured by `frontend/.env.local`. Run the migration against any different deployment database before releasing the dashboard. The role change invalidates the owner's previous sessions, so sign in again.

Before a broad production release:

1. Exercise real microphone permission, speech recognition, audible output, interruptions, unplugged devices, navigation during connection, packet loss and reconnect/hang-up across representative desktop/mobile browsers. The headless provider check establishes actual provider connectivity and audio generation, not a measured conversational quality or latency SLA.
2. Complete interactive deployed Google plus enrolled TOTP sign-in and real owner navigation after deployment. Server authorization and session-format tests passed; they do not replace the interactive identity-provider flow.
3. Validate real trusted ingress headers on the hosting platform. Local production `next start` intentionally cannot establish demo network identity without the platform header. Voice stays unavailable in that condition; account/admin access now remains functional. Do not fix this by trusting arbitrary forwarded headers on a publicly reachable server.
4. Browser-local workspaces are device/origin storage, not per-account encrypted cloud storage. Signing out does not erase that device's workspace. Use separate browser profiles on shared devices and explicit backups. Cross-device company membership, account-specific workspace migration, retention/deletion and lost ownership-grant recovery require further product work.
5. Establish measured load/concurrency limits, provider spending caps, deployment-specific alerting/log retention, database least-privilege credentials and backup/restore drills. Counters and local tests do not establish capacity. Database role constraints defend application mistakes; database-owner credentials can alter the schema.
6. Test configured SMTP acceptance/bounces, native telephone transfer, signed post-call webhooks and connected workspace mode against their actual deployment. They are disabled in the inspected default configuration. Container/private scanner/sandbox deployment gates in the retained backend documentation still apply if that backend is activated.
7. Complete a broader physical-device accessibility and keyboard pass, including screen readers. Existing routes and workflows were inspected/tested selectively; this pass does not claim every dialog and every device combination was exercised.
